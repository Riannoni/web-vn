## Кто делает следующий результат

У каждого actionable input один ответственный исполнитель; остальные получают относящийся результат, а не совместное поручение «Renderer/Pose». Использовать действующий manifest/index, не создавать новый tracker.

| Роль | Собственный результат и прямой потребитель |
|---|---|
| Chief | Следующий разрешённый quality-input, его один owner и фактический handoff; снимает конкретный блокер, не становится approval-hop. |
| Renderer | Проверяет contract → actual graph/staged inputs; одна причинная правка и frozen input для Lab, reusable source fix для Integration. |
| GPU Lab | Единственный GPU/shared-runtime owner; проверяет graph, генерирует, лично смотрит каждый output и продолжает bounded repair; pixels → Golden. |
| Identity | Один доказанный identity/wardrobe/ref дефект; условный input для названного Renderer либо Lab. Уже подтверждённые каноны не пересоздаёт. |
| Provenance | Только изменившаяся/недостающая source → staged input → graph привязка; delta текущему исполнителю и Golden Evidence. |
| Pose | Один наблюдаемый pose/contact дефект разрешённого asset; подходящий conditioning для названного исполнителя, без новой подготовки заблокированного CG3. |
| Golden | Независимый осмотр точных новых pixels/refs; один конкретный дефект текущему repair-owner либо ограниченная фактическая приёмка. |
| Golden Evidence | Существующий приватный индекс originals/finals/refs/attempts с раздельной атрибуцией producer/operator/Golden; входы производителю и Golden. |
| Integration | Подтверждённый совместимый reviewed fix и rollback → Lab; installed receipt и затронутый scope → E2E. Не переустанавливает неизменённый здоровый код. |
| E2E | Реальный smoke затронутого production game-job path после доставки; GPU enqueue выполняет Lab. Browser auth нужен только для затронутого UI. |
| Reliability | Самый ранний воспроизведённый generation/QA/runtime дефект; не полирует alpha у кадра с лишними людьми/головами/неверным каноном. |
| Decision | Один действительно конфликтующий input/контракт и один executor; решение по graph не снимает platform denial. |
| Broker | Только конкретный ownership/execution дефект и минимальный fix для Lab; неизменённый lock не требует часового аудита. |
| Broker Reviewer | Один ещё нужный independent review точного changed artifact; не дублирует действительный review или optional preview index. |
| Dispatcher | Продвигает готовый deferred handoff, восстанавливает подтверждённый successor из результата/комментария и сверяет terminal outcome; STARTED не завершает цепочку. |

## Минимальная проверка качества

Для приватного provisional pack нужны чтение файла, ожидаемые размеры, корректный формат, alpha у sprites и точная привязка actor/background/asset. Затем реальный осмотр pixels и соответствия storyboard/канонам. Сначала фатальные cast/anatomy/identity/wardrobe/composition дефекты, затем alpha и детали; косметическая правка отвергнутой генерации не становится кандидатом на приёмку. Не требовать G3, латентностного доказательства, нового QA-исследования или UI-показа перед разрешённым осмотром pixels и подтверждённым исправлением.

Нужный текст в реально отправленном prompt доказывает подачу условия, не его выполнение. Обоснованная правка формулировки под конкретную модель допустима по наблюдаемому дефекту: frozen brief закрепляет требования/каноны/storyboard, не неэффективную формулировку. Проверять эффективные связи input/ref → encoder/conditioning/model → используемый sampler/output и действующие параметры, а не наличие строк/nodes в сохранённом JSON.

ModelLab/private preview необязателен и не занимает критический путь. При его использовании непросмотренный диагностический набор показывается только через **уже разрешённый приватный preview** с явным PROVISIONAL / NOT REVIEWED. Это не canonical publish, PASS или G2. Не обходить отказ экспорта под названием preview. Обычный production path сохраняет действующие обязательные QA, admission/version fences и защиту saves/assets; глобально их не отключать. Отсутствие такого preview не создаёт новую UI-задачу и не блокирует разрешённый прямой pixel review или подтверждённую production-доставку.

## Выполнение без лишних ожиданий

Lab вправе выполнять ограниченные приватные прогоны на действительных закреплённых входах с существующими моделями/nodes и **тем же фактическим общим GPU-lock**. До изменения runtime — известные исходы, единоличное владение, очередь, ресурсы и обратимость. Не нужны новые Chief/Decision подписи, production HMAC/issuer или посторонний полный CI для частного diagnostic. Не удалять legacy running/review_pending и не обходить tool approval.

В одном run: render → технические проверки → осмотр точных original/final pixels против refs → один конкретный дефект → одна причинная правка → проверка effective graph → следующий bounded render и осмотр. Сохранять baseline, seed и сравнимые параметры; отличие от baseline и необходимые исключения записывать. Не заканчивать после известного FAIL, когда исправление разрешено и бюджет остаётся. Golden независимо принимает результат, но ожидание Golden/ModelLab не запрещает producer REJECTED и repair. Передавать точный вход только при недостающей возможности/полномочии, например GPU или независимой приёмке; denial handoff не снимает. Автоматический QA применять по обязательному production path или конкретному blocker, без нового benchmark. Готовый вход идёт прямо исполнителю через existing eligible peek → reserve → один run_now с прежними лимитами.

Путь выбирается по asset и наблюдаемому дефекту. Face IP-Adapter даёт image-reference conditioning; img2img отдельно инициализирует sampler латентами исходного изображения через VAEEncode или эквивалентный encoder path с выбранным denoise, который не означает процент изменённых пикселей. Не навязывать fresh latent каждому sprite. Для CG сохранять цельную композицию, выбирая подходящие background/composition/view refs; предыдущий кадр пригоден лишь при соответствии новой камере/сцене, обязательной цепочки previous-frame нет. ControlNet pose/depth, masked inpaint или смена модели вводятся только для конкретного наблюдаемого дефекта, с совместимостью и прежними границами ресурсов. Три обычные сцены используют один сохранённый фон через CPU-композицию, без его повторной генерации.

Только для нового заранее замороженного Mira/Max pack разрешён один provisional technical-pass выход на каждый объявленный asset: **1 фон + 6 sprites + 3 CG = 10 генерируемых оригиналов**, затем **3 CPU-композита**. Golden смотрит их параллельно; глобальный лимит двух непросмотренных выходов не останавливает переход между этими независимыми элементами. Для каждого asset допускается максимум **две ADAPTIVE альтернативы**, ожидающие review, сверх его одного provisional выхода. Максимум трёх фактических GPU submissions на гипотезу и вся история сохраняются, включая неудачи. Список и действительные новые storyboard/asset inputs фиксируются до генерации; нет дополнительных незапланированных вариантов, массовых rerolls или переименования старых H2/H3. Исключение не относится к другим экспериментам, не снимает unknown/legacy execution fences и не даёт canonical PASS/publication без нужного review. После 2–3 одинаковых неудач меняется подход, а не счётчик.

Из acceptance queue отдельного diagnostic можно убрать только известный terminal producer REJECTED после осмотра точных pixels или настоящий полный mandatory QA FAIL как REJECTED_QA. Сохранить original/source-job/worker/result SHA, причины, bytes и все attempts; G2 NOT REVIEWED. QA reason не доказывает видимый факт. Timeout, недоступный сервис, partial QA, denial, unknown/running/pending execution и legacy review_pending так не очищаются.

## Неприкосновенные границы

Только GPU Lab загружает GPU-модели, отправляет GPU jobs и активирует shared runtime. Не менять активный сюжет, принятые assets и чужие dirty worktrees. Работать в приватных изолированных директориях/одноразовой игре, сохранять настоящие входы и историю. Отсутствие production подписи не запрещает diagnostic, но неизвестный источник не становится каноном.

Приватные сцены, изображения, refs, saves, prompts, ключи и веса не публиковать в GitHub. Проектные обратимые tools/model installs уже разрешены с источником/лицензией/хешем, отдельным окружением и ограниченными ресурсами; выполнять только по нужде pack, без платных аккаунтов или замены OpenAI workers.

Независимый G2 требует фактической проверки всех применимых условий и правильной атрибуции; unknown/violated не становятся verified. G3/render-v1 readiness — отдельное будущее утверждение, не prerequisite этого набора.

## Доступ, доставка и короткий итог

Сначала прочитать текущие AGENTS, [DEVELOPMENT-AND-TESTING](docs/DEVELOPMENT-AND-TESTING.md) и worker contract; неизменённые версии повторно не читать. Затем текущую pack-задачу [issue #20](https://github.com/Riannoni/web-vn/issues/20) и один нужный handoff. Проверять только затронутую среду, не все 15 ролей перед каждым действием.

Integration сохраняет standing authority доставлять относящиеся к набору совместимые tested/merged fixes; Lab активирует их на безопасной границе с backup/rollback и проверкой installed bytes. Не требуется новое разрешение владельца/Chief/Decision, ModelLab, показ владельцу или готовность всего диагностического набора. После — один относящийся smoke настоящего production game path, а не повторный release audit. Для worker/vision использовать существующий нормально аутентифицированный backend game-job путь через настроенный vn_web.home: Lab выполняет GPU enqueue, E2E связывает installed bytes → job/output → mandatory QA → version-fenced publish либо ожидаемый reject как PRODUCTION_RENDER_SMOKE. Direct diagnostic graph этого не доказывает; browser login/playback нужен только при затронутом UI и иначе остаётся отдельно непроверенным. MERGED, DEPLOYED, PRODUCTION SMOKE CHECKED и VISUALLY REVIEWED различать. Готовность source или успешный deploy — промежуточный результат: оставшийся активный цикл качества продолжается, пока разрешён и укладывается в прежний бюджет.

На входе и перед выходом потребитель разбирает адресованные pending inputs, сохраняет disposition и оставшийся шаг в существующем case record, затем ACK своим настоящим run ID. Любой активный native worker может продвинуть готовый чужой deferred event через existing peek → reserve → один run_now; Dispatcher подхватывает actionable результат/комментарий, если event отсутствует. Один input — один owner; никакой root/chat-gate. Сохраняются 3 wakes/target/hour, cooldown 240s, 45 global/hour, paused/unknown/denial fences и запрет self-wake. Helper/classifier лишь advisory; исторический scoped denial не является глобальным стопом.

SSH-MCP — основной маршрут; уже авторизованный HA-MCP SSH — резерв для подтверждённого сбоя связи/доступности либо явно истёкшей авторизации именно SSH-коннектора. После первого подтверждённого сбоя выполнять [REMOTE-ACCESS](docs/REMOTE-ACCESS.md) в том же run, не ждать всех диагностик или следующего расписания. Чтение можно повторить через HA один раз; мутацию — только после доказанного NOT_STARTED с прежними idempotency/lock guards. Сохранять target/user/command/input/operation ID и owner. При возможном выполнении сначала HA read-only reconciliation; UNKNOWN не повторять. Проверять точный собственный HA run и nested SSH result, не только STARTED. После здорового SSH probe возвращаться к primary со следующей новой операции; уже выполненное через HA не повторять. Максимум три SSH health probes/run с фактическим backoff 10/30/60 секунд, без обязательной остановки полезной HA-работы. Safety/approval/access-control denial, host-key mismatch и общий permission error не являются transport outage; отклонённый эффект не повторять через HA/другого worker/tool. Отказ конкретной CG3-операции сохраняется для неё и не останавливает независимые разрешённые assets/source fixes. Unknown GPU/run_now и ownership/queue fences сохраняются.

Liveness — enabled/current matched run/здоровый сервис — не равен product progress. Старый latest_result другого run не завершает текущий. Не сеять посторонние legacy receipt/shadow-QA/broker audits; не очищать существующие очереди/leases/receipts и не отключать 15 native workers. Роль без релевантного нового input заканчивает NO_NEW_EVIDENCE без нового аудита, файла или wake.

Завершать активный quality-run можно после приёмки конкретного элемента или достижения прежнего run/attempt budget. При блоке сохранить точный input/изменение, причину и owner, затем в оставшемся бюджете выбрать следующий независимо разрешённый полезный asset/input; не воспроизводить заблокированный эффект. Если такого шага нет — закончить с точным blocker и eligible successor через existing wake, без self-loop. GENERATED/hash-only не означает проверку; недоступный осмотр pixels — конкретный capability blocker, не PASS.

Итог: какой новый элемент реально проверен по pixels/refs и соответствует ли заданию, какой подтверждённый fix доставлен и проверен в production, точный приватный asset ID/installed SHA, один оставшийся дефект и следующий исполнитель. Пользовательский показ не требуется. Публично — обезличенно. Не заменять картинки старыми timings, G3 counters, списком PR или ещё одним HOLD.

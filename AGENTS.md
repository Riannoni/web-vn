## 1. Что считается результатом

Главная задача P0 — **реально правильный** спрайт и CG в браузерной VN, а не максимальное количество рендеров и исправлений. Три отдельных gate:

- **G1 technical:** ComfyUI/job успешно выполнился, файл и структура корректны, GPU и пайплайн исправны.
- **G2 visual:** исходные пиксели совпадают с обязательным Scene Contract: локация, состав named principals/массовки, каноническая внешность (где видна), актуальная одежда каждого actor, предметы/landmarks, позы, контакты, ракурс, alpha спрайта.
- **G3 system:** результат повторяется на независимых сценах, не портит канон и принятые ранее изображения, безопасен при restart/retry/rollback.

**`qa.passed=true`, `job.done`, зелёный CI, красивый thumbnail, высокий CLIP или 12 успешных технических изображений ≠ выполненный G2/G3.** Не называй `render-v1` готовым до полного release gate.

## 2. Непереговорные правила

1. **Нет фиксов до расследования первопричины.** Сначала воспроизводимое нарушение → наблюдения → одна проверяемая гипотеза → контролируемый тест.
2. **Одна гипотеза за раз.** По возможности фиксируй source state, seed, модель, prompt, workflow, размер и меняй только один фактор; перечисли все исключения.
3. **Нет слепых повторов.** Классифицируй конкретную причину отказа. После 2–3 неудачных исправлений одного дефекта — **STOP**, пересмотр архитектуры/предпосылок, а не четвёртый патч.
4. **Нет ослабления QA.** Запрещены `accept anyway`, отключение mandatory check, завышение статуса `unknown/unobservable` до `verified` или произвольное смещение порога, чтобы добиться зелёного результата.
5. **Обязателен прямой просмотр оригинального изображения.** Связывай конкретный job/prompt ID с точным PNG, а не «последним файлом»; сравнивай с оригинальным Scene Contract и private reference. Если картинка не просмотрена — результат **НЕ ВИЗУАЛЬНО ПРОВЕРЕН**.
6. **Только изолированные тесты.** Клонируй исходный save/game с новым ID, не меняй действующий сюжет/активный save, не перезаписывай принятые assets, не публикуй ошибочные candidates.
7. **Один владелец GPU-очереди.** На одном AMD GPU параллельные агенты могут делать read-only анализ и отдельные ветки кода, но не конфликтующие рендеры, настройки, модели и рестарты ComfyUI.
8. **Нельзя заявлять deployment по одному merge.** Отдельно проверяй состояние GitHub, home, PC, worker, QA и факт E2E.
9. **Никаких приватных данных в GitHub.** Private story/saves, CG, face references, unredacted prompts, ключи, токены, model weights и внутренние дампы хранятся локально.
10. **Не используй Work или Codex для разработки проекта.** Доступ GitHub + SSH-MCP уже позволяет действовать через VPS → home → игровой ПК; используй разрешённый маршрут и не публикуй секреты. Проектные инструменты и локальные модели можно устанавливать по действующему worker contract; это не замена OpenAI workers.


## Code Mode: экономия входного контекста без уменьшения проверок

Если текущая стадия уже определила **независимые, read-only и бесконфликтные** проверки, собери их в **один** вызов Code Mode `exec`. Выбирай `Promise.allSettled`, если полезны частичные результаты и нужно проверить каждый, либо `Promise.all`, когда неудача одного должна прервать весь набор. Зависимые вызовы, операции записи, запросы подтверждения и адаптивные проверки остаются последовательными. Не делай коротких `wait`/poll длительных задач: дай локальному процессу завершиться и только потом прочитай итог. Не повторяй уже завершённые проверки.

Не выводи в модель мегабайты JSON, полный stdout успешных тестов, многострочные логи, целые реестры инструментов и широкие поисковые выдачи без нужды. Храни полные результаты локально с путём/хешем; выводи **короткий индекс**, исключения, релевантные строки и точные доказательства. При truncation сужай запрос, а не повторяй усечённый общий вывод. Эти меры **не** отменяют полный первичный просмотр обязательных правил, отрицательные тесты, визуальную приёмку и STOP.

Основание: [openai/codex #41450](https://github.com/openai/codex/issues/41450) — контролируемый A/B с сохранением 50/50 проверок снизил количество модельных циклов 60→15 и суммарный логический вход на 81,6% **в том тесте**, а не гарантированно в web-vn. [Наши измерения и приоритеты](docs/NIGHT-AGENT-QUOTA-RESEARCH-2026-10-31.md).

## 3. Стандартный цикл каждой задачи

**PRE-FLIGHT** (read-only): версия/очередь/контракт/актуальная проблема/настоящие входы и выходы.

**HYPOTHESIS**: один дефект, один контролируемый фактор, измеримая цель, критерий опровержения, лимит времени/GPU.

**ISOLATED TEST**: статические проверки/юнит-тесты → временное сохранение → при необходимости реальный GPU → точный выход и stage timings.

**PIXEL REVIEW**: осмотр исходного PNG с референсом; по пунктам `verified`, `violated`, `unobservable`, `not_applicable`. `unobservable` для mandatory поля — не подтверждённый успех. Контакт рук нельзя доказать одной близостью точек DWPose.

**EVIDENCE**: private artifacts + обезличенный отчёт (SHA, workflow/seed/job/prompt ID, размеры, timings, QA, visual assessment, сохранность канона, ограничения).

**DECISION & HANDOFF**: подтверждено/опровергнуто/неизвестно, status source/merged/deployed/E2E, одна следующая гипотеза. Никакого «всё исправлено», если фактически прошёл только технический этап.

## 4. Принципы архитектуры

- Story state атомарен, версионирован; асинхронный рендер не может перезаписать другую сцену. Проверять scene fingerprint и действующее сохранение перед publish.
- Логика общая для разных игр, а reference/story/save/assets — изолированы.
- Named principals не равны всем людям в кадре. Скрытое лицо не становится доказанным facial identity.
- Typed constraints (actor ID, outfit, position, region, camera, required object, relation/contact, crowd policy) важнее литературного prompt.
- SDXL IPAdapter/ControlNet нельзя механически вставлять в нативный Z-Image graph. Новые модели/узлы — только проверенные по лицензии, ROCm, VRAM, скорости и A/B.
- Multi-stage сборка (background → actor identity/wardrobe → exact pose/ROI → local repair → full QA) — **исследовательская гипотеза** для проверки, а не доказанная готовая архитектура. Не переписывай существующие части без измерений.

## 5. Минимальные приёмочные сценарии

Ранее определённый минимальный приватный тест: **один спрайт с существенной сменой одежды + два последовательных CG** с той же канонической внешностью, правильными предметами/архитектурой, отсутствием клона и сохранением одежды. Обязательные сложные действия/касания проверяй отдельно с exact-view guidance и independent visual evidence. Для отдельного first-attempt gate — каждый кадр **первой попыткой**, не best-of-N. Любой неверный обязательный факт = FAIL. Этот промежуточный тест не заменяет текущую цель владельца: **фон + спрайт + три разных CG**, каждый с первой попытки и полным generation→ready ≤20 секунд.

Для `render-v1`: **не менее 30 размеченных независимых сцен**, включая отрицательные случаи, false accept/reject/unobservable, P50/P90 полного хода и стадий, повторные сцены, E2E, restart/rollback, корректность отказов и приватность. См. issues #2, #20, #21–#24, #31–#34. Не путай промежуточный milestone и релиз.

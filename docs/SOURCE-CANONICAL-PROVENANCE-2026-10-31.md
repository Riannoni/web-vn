Read `AGENTS.md` and `docs/DEVELOPMENT-AND-TESTING.md` first. Master issue #20, source tasks R-10/R-11, Golden #76, identity lane, GPU broker draft PR #78.

## Evidence chain and authority boundaries

1. **Canonical game save:** a successfully committed `gameNarrate` on the game server writes player action, narrator messages, `turn_metrics.last.action_id`, current `game.version`, `scene.cg_revision`, `scene.image_prompts.cg`, normalized principals, requested wardrobe/pose, typed contacts, crowd and camera. It must NOT be reconstructed from a reviewer-authored test description. A previous turn or narrator-prompt mismatch is explicitly labeled `incomplete_not_narrative_verified`.
2. **Real enqueue:** only `src/jobs.mjs:enqueue`, for `kind=scene` and `composition=neural_story`, derives `spec.source_provenance_v1` using `src/source-canonical-provenance.mjs` **before** queue/supersession writes. Pure `artSnapshot` used for preview/planning remains unchanged. Any missing canonical face, mismatched named actor, broken body/face ref, missing contact hand, silently dropped contact, nonmatching camera/wardrobe or stale scene fingerprint rejects at source. The source record binds game/version/revision, actual action+latest narration message digests, stored narrator CG prompt digest, typed contract digest, canonical actor face/body names, requested outfit/pose, contacts and origin tags. It is only **source intent**, not proof pixels match.
3. **R-10 signed enqueue — dependency NOT merged here:** R-10 local commit `35b6cd40c624ee52c249a8cab8a4ffaf606a40d2` implements the producer `VN_CREATION_RECEIPT_HMAC_KEY` signature at actual queue creation, including the complete `spec` hash, actual save snapshot/version, source background and actor face/body file-byte SHA. Only after combining this change with R-10 is the proposed `source_provenance_v1` tamper-evident. Unsigned source JSON alone has **no immutable authenticity**. R-10's test fixtures with only a body anchor must be updated to include the required canonical face reference.
4. **R-11 signed GPU result — dependency NOT merged here:** R-11 local commit `d9e81d6c4514bbff9e01731fbc3cbc45f877c1d1` signs append-only `intent → dispatch → result → final` with a distinct `VN_RESULT_RECEIPT_HMAC_KEY`; binds job/attempt, producer signature, assembled workflow SHA, Comfy prompt ID, exact original output PNG SHA and final output file-byte SHA. The independent function `verifyOriginalImageChain` checks those exact signed phases against *the original bytes* and required source face/background hashes. Synthetic, cross-scene, stale attempt, wrong prompt, forged graph or missing pre-submit intent must fail. A worker HMAC is **not** independent cryptographic attestation by Comfy itself.
5. **Golden / reviewer — separate #76 work:** a trusted verification service, with keys kept in its secret storage, verifies the chain and provides an authenticated redacted receipt with job ID, prompt ID, original PNG SHA, contract SHA and review scope. The Golden reviewer independently obtains **the same original full-resolution PNG**, private canonical face/outfit/scene references and checks each mandatory typed field. Merely validating signatures returns `g2=NOT_REVIEWED`. It must NEVER turn the absence of original pixels, visible face, camera or contact into PASS. Reviewers must **not** receive production HMAC signing keys; if the verifier itself holds symmetric keys, it can forge receipts and should be treated as part of the trusted computing base, not an independent signer.
6. **Publish/E2E:** R-11 server publish must rehash the exact final bytes and revalidate current scene/save fence and source digest. Broker #78 must enforce one real GPU submit owner before any controlled end-to-end deployment. G1 output is separate from G2 original-pixel review, browser E2E, and ≥30 human-labelled G3 cases.

## Source gaps observed

- Main `src/jobs.mjs` currently has no creation-time original-source signature; `src/art-spec.mjs` allows a body-only anchor and `src/scene-contract.mjs` silently filters contacts for unknown actors. A narrator-provided positive prompt may differ from the canonical `scene.image_prompts.cg`; legacy test fixtures even incorrectly set `narrator_prompt:true` on arbitrary strings. This source gate marks mismatch unverified rather than misrepresenting it.
- Current deployed `worker/worker.py` still sends directly to Comfy `/prompt`; R-11's signed pre-submit/result logic is source-only. An empty Comfy queue is not an exclusive owner; unresolved submits must not be silently retried.
- A canonical face file being present and byte-hashed proves provenance of the reference, **not that Z-Image conditioned on that face** or that output face matches. For the current fast T2I route identity-conditioning has not been demonstrated. Identity Engineer owns that physical model/generator evidence; this PR does not touch its graph.
- Sprite and background source/creation chains are NOT yet uniformly signed: this minimal gate covers neural CG. The target first-shot pack (BG + transparent changed-outfit canonical sprite + 3 linked CG) is **not** thereby achieved. No 5/5 G2 or first-shot claim.
- The original PNG SHA is verified offline from supplied original bytes, but Comfy's `history` mapping and independent file-to-job acquisition must still be checked by the reviewed broker/reviewer. HMAC keys are symmetric: two keys are distinct signers in separate trust zones only if their distribution truly is isolated.
- Out-of-band edits to job JSON or source files are caught only after combined R-10/R-11 signatures and byte checks are deployed. Creation-time integrity cannot be retroactively asserted for existing unsigned jobs. Old jobs should remain legacy/untrusted, not magically migrated or marked passed.
